旁白使用macOS内置中文声音Tingting，在本机离线生成。它是合成声音，没有模仿或克隆任何人的声音。原先尝试的在线语音未使用，发布构建无需该服务。

## 画面与操作的来源

本次新建独立模拟环境，用同一条提醒验证创建、去重、公告保留及来源恢复。该任务从3%阈值改为4%后，再打开原通知，确认其中仍保留3%条件及96.2元的判断依据。现有公开体验实例的访客任务没有用于这些写入验证。

成片采用实际操作过程中取得的界面画面，并保留部分短段的真实界面变化。指针、点击环、标题、字幕及镜头运动是后期制作。部分等待过程经过剪辑，成片不作为连续录屏或运行延迟的测量证据。画面里的价格与公告均为模拟数据。

浏览器截图曾返回1280×720与1265×712两类尺寸。制作时先统一到1280×720，再在固定的16:9展示区域内构图。镜头的取景范围限制在源图之内，字幕放在画面下方。控件点击位置来自操作时保存的页面坐标；未记录位置的过渡保留为切镜，不补造点击位置。

录制时的应用源码摘要单独保存在视频元数据中。随后补充了播放页，并修复导航切换沿用旧页面滚动位置的问题。提交包另记当前源码提交号；录制源码与交付源码不会混写成同一份记录。

## 可复用的制作文件

`scripts/cinematic_story.json`保存章节与逐句旁白。`scripts/build_cinematic_voice.py`生成逐句音频，确认文件中有实际音频样本后才进入下一步。`scripts/build_cinematic_demo.py`使用源图及选定短段生成视频、封面和字幕。`scripts/verify_demo.py`读取实际编码流进行交付检查。

```bash
pip install -r requirements-artifacts.txt
python scripts/build_cinematic_voice.py
python scripts/build_cinematic_demo.py
python scripts/verify_demo.py
```

语音构建需要macOS自带的`say`及已安装的Tingting声音，音视频导出需要FFmpeg。通过`RADAR_CAPTION_FONT`指定本机中文字体。仓库不分发字体文件。系统声音随操作系统变化可能产生不同音频；保留下来的文本、源图与摘要用于解释具体发布版，未宣称跨系统逐字节一致。

成片放在发布附件中，逐句音频可按讲解稿在本机重新生成。用于成片的源图、选定短段及位置记录与脚本一起保留，完整的本地捕获日志另行保存。旧视频和旧提交包继续保留，便于回看。

## 发布检查

`verification.json`必须与实际MP4的SHA256相同。检查脚本要求存在一条视频流及一条旁白音轨，视频为1080p、30帧，声音为48kHz AAC。章节需要覆盖完整视频，字幕按时间顺序排列且不越界，文字与讲解稿逐句匹配。

声音通过响度与真峰值检查，并对整个文件解码。技术检测能发现缺失音轨、损坏文件和过量峰值；合成声音的自然程度仍需要听者判断。视觉检查使用输出关键帧核对构图，不能替代真实首次使用者的理解测试。

`scripts/build_submission.py`在打包前重新读取实际视频流，并要求最终验证记录匹配。ZIP包含离线播放入口，生成后逐个核对文件摘要并检查压缩包完整性，超过30MB会阻止交付。

本轮回归为122项Python测试及16项前端逻辑测试。新增9项检查防止无音轨视频、错误画幅、超时长、章节断档及字幕重叠再次进入交付流程。原始输出见`artifacts/cinematic-v1.2/`。这些测试结果不代表真人体验成功率或生产服务可用性。
