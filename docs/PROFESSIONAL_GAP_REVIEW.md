# 与成熟同岗交付相比：差距、补齐结果和上线条件

评审日期：2026年9月21日。对象：照看，同花顺 AIME 金融智能 Agent 产品经理笔试项目。

“工作三年”不能直接换算为统一的产品质量。这里采用可检查的标准：一名能独立负责同类产品交付的产品经理，需要说明服务对象与取舍，让用户独立完成操作，并用证据证明系统处理了失败和长期运行问题。以下为本次代码、页面与交付材料审查发现的全部重要差距，不宣称覆盖未来所有故障。

这份清单区分代码已落地、设计已明确和仍需外部条件验证。写完方案不会自动关闭真实数据、用户研究或托管方面的缺口。

## 对标的用途

TradingView 的提醒设置把条件、频次、有效期与通知方式分开说明，这里用于检查用户能否核对每项设置。[官方说明](https://www.tradingview.com/support/solutions/43000595315-how-to-set-up-alerts/)

Stripe 的幂等请求机制提供了可靠重试的参考，这里落实为同一创建操作的重试识别和参数冲突处理。[官方说明](https://docs.stripe.com/api/idempotent_requests)

Google SRE 的用户旅程与服务指标方法用于明确指标的分母、采样窗口和行动条件。这里没有照搬别人的可用性目标。[官方说明](https://sre.google/workbook/implementing-slos/)

Cloudflare 明确把 Quick Tunnel 用于开发和测试，且不提供SLA。它解释了当前部署缺口，不能当作上线完成的证据。[官方说明](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/)

这些来源支持具体机制，不构成某家公司“最顶尖”或模仿后必然获得offer的证明。

## 真人首次使用验证：方案已准备，结果尚未取得

招募5名有A股自选股、未看过项目说明的人，作为第一轮问题发现样本。5人是执行方案中的人数，不是统计代表性保证。让每人独立创建一条提醒，修改阈值，找到未触发原因，再解释一次来源异常。操作中不提示按钮位置，只有卡住或放弃时记录原因。

逐人记录任务是否完成、首次提醒是否被找到、是否把模拟数据当真、是否以为会有手机推送。访谈原话与产品解释分开保存，经同意后保留必要记录。出现危险误解时先修正文案和流程，再让新用户复测；不把熟练测试员的成功当成新用户成功。

## 指标与成本的下一步

当前运行页显示当前浏览器的事件次数。真正的用户转化需增加经授权的匿名访客/会话去重，分别计算“开始创建的人中有多少确认开启”“生成提醒的人中有多少打开通知”，并分开首次与重复使用。尚未收集的数据不填估计值。

字段正确率须对照预先写好的人工期望，按公司、比较符号、数值、持续时间及组合关系分别判定。来源漏报率需要完整参考公告流。用户说“有用”只能说明主观反馈，不替代字段正确率或完整性评测。

成本预算分开计算模型、行情和公告。模型费用由实际输入/输出token乘以当期服务单价；行情与公告按调用次数和供应商授权计费。若有N条任务，平均间隔为I秒，检查时长为T秒，尚未做跨任务复用时，每类所需来源约为N×T÷I次调用；失败重试需另外计入。实际开市窗口、缓存和供应商限流会改变结果，不能把这个公式写成已发生费用。

## 故障与恢复的执行次序

先判断网页是否可用、调度是否仍更新，再查看具体任务的数据源结果。保存异常记录后，仅暂停确实受影响的规则或来源。恢复后核对待提醒公告是否送达，以及去重是否继续生效。无法还原停机期间的价格路径时，应保留中断区间，避免给出完整监控的印象。

生产部署前先在隔离主机恢复最近备份，检查任务、规则版本和通知能否读回，再切换服务。没有恢复演练证据时，不把“已有备份文件”写成“恢复保障已经完成”。
