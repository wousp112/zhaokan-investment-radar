# 照看：对标选择与改版验收

核对日期：2026年9月21日。主要读者是负责下一轮改版的产品、设计和开发协作者。

这份文档把同花顺笔试要求转成评审维度，并为每个维度选择具体参考。评审维度来自题目与岗位职责，优先级是本项目的判断；没有取得招聘方的内部评分表。列出的产品具有直接可借用的做法，不代表已证明它们在该维度排名第一。

## 本轮事实与交付范围

前一轮已读取Gemini反馈并核对旧版页面及源码，发现英文口号、调度心跳、技术版本与模拟故障按钮集中在日常工作台；暂停状态的辅助说明也有歧义。这些是改版前的问题记录。

2026年9月21日已实施新的工作台、条件设置、检查记录和独立演示页，并更新使用帮助。原始规则模型与后端比较逻辑保持不变。价格阈值通过单独的显示转换层编辑，保留严格比较和包含边界。

本轮实际查看了工作台与条件窗口的截图，并用原生Chrome操作核对创建、修改、去重、公告保留、故障恢复、版本恢复及手机入口。其余截图已保存，部分验收依据来自DOM和元素尺寸。没有完成参考产品登录后同一状态、同一视口的逐像素对照；不将结构参考写成视觉克隆认证。参考来源仍为官方设计文章与官方指南。

新公网入口已经完成真实DeepSeek解析、创建模拟提醒和触发验证。实现、截图及测试范围见[改版验收记录](REDESIGN_ACCEPTANCE.md)。历史演示视频尚未重录。

## 先固定主对标

工作台的视觉结构统一参考 [Linear 的官方界面改版](https://linear.app/now/how-we-redesigned-the-linear-ui)。同一套导航、页面标题、列表密度和详情区域贯穿产品。金融信息顺序与条件配置分别借用 Apple 股市和 TradingView。其他参考只解决对应行为，不再额外引入一套配色或按钮样式。

| 可行路径 | 主要参考 | 优点 | 取舍 |
| --- | --- | --- | --- |
| 提醒管理工作台，本轮采用 | Linear 的工作台结构，TradingView 的提醒设置 | 创建、查看状态和处理异常能够围绕同一列表展开 | 保留金融信息，避免变成通用项目管理器 |
| 自选股优先 | Apple 股市的自选列表与详情 | 公司及行情关系直观，适合日常查看 | 需补足多任务管理与数据异常入口 |
| 金融终端优先 | TradingView Supercharts 与提醒管理 | 监控与行情设置在同一上下文 | 当前没有完整图表数据，不复制复杂图表工具栏或伪造分时线 |

采用一个主对标，可以按组件复用成熟做法。每一次偏离都应能说明具体的业务原因，例如本项目只有站内提醒，不能沿用 TradingView 的邮件通知设置。

## 评审维度、对标与可检查的改法

| 中文是否自然、准确 | [Ant Design 文案规范](https://ant.design/docs/spec/copywriting-cn/)：用户熟悉的语言、明确动作、准确时间及一致命名 | 按对象和结果写按钮；技术字段退出主界面；同一动作在各页使用相同名称 | 没有英文口号、哈希和模型耗时占据主界面；没有不具备依据的“安全”“平稳”判断 |

| 测试是否干扰普通使用 | [Stripe Sandboxes](https://docs.stripe.com/sandboxes)：测试环境与真实集成隔离 | 单独设置“演示体验”，只在那里显示故障情景；同一设计系统下清楚显示数据模式 | 普通任务卡片不含15个测试按钮；切换模式不会把模拟数据改称真实；真实任务不能被注入情景 |
| 错误与确认是否适度 | [Apple Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts)：信息提示尽量就地，重要且不可撤销的操作保留确认 | 输入错误留在输入框附近；原文保留；归档使用清楚的应用内确认 | 错误不靠短暂浮层承载；取消归档无变化；没有尚未实现的撤销按钮 |
| 手机与键盘能否完成主任务 | [Linear 跨平台和多状态验证](https://linear.app/now/how-we-redesigned-the-linear-ui)：按环境、外观及信息层级检验各视图 | 手机保留公司、状态和主要操作；次要信息进入详情；补齐焦点与键盘流程 | 在窄屏完成创建、修改、查看依据和暂停；放大文本不丢关键内容；键盘可进出对话框。这些是本项目验收标准，不声称来自已完成的移动端实测 |

## 逐屏改版目标

### 我的提醒

左侧导航保留“我的提醒”“提醒记录”“使用帮助”。“演示体验”有独立入口。顶栏呈现页面标题和新建操作，去掉全大写英文、固定头像装饰及宣传段落。

每条任务优先展示公司、规则摘要和状态，最近检查作为次要信息。`v1`进入修改记录；调度心跳进入运行详情。没有任务时，只说明可以创建什么，并给一个可点击的例子。

行情上下文只使用能够取得并校验的实际值。真实数据不可用时保留缺失状态，模拟行情始终标明。没有分时数据就不画伪分时线；没有历史回测就不显示预计触发频次。

### 创建和修改

自然语言优先识别公司；公司选择作为可修改的已识别结果。同一提交保留唯一、明确的标的。输入中的公司与手动选择冲突时，要求确认具体公司，不静默覆盖。

确认摘要示例：“未来14天，贵州茅台较昨收下跌达到3%，或出现新的业绩预告时，保存一条站内提醒。”确认按钮为“开始监控”。示例依赖当前草稿字段生成，不能固定写死14天或3%。

条件编辑使用专业但易读的词，例如“低于”“不高于”“超过”“达到”。下跌条件以正数显示时必须同步翻转比较关系，底层仍使用准确的比例值。涨跌方向切换、临界相等及严格比较分别回归验证。

提醒间隔和价格检查时间放进“更多设置”。模型名称、耗时及完整任务 JSON 属于“技术详情”，保持可核对，不占据默认确认流程。AI开关移出主创建区；运行路径和外部模型使用在设置与解析记录中如实说明，模型回退有提示。

### 检查详情与提醒记录

默认说明“实际值是什么、设定条件是什么、本次作了什么处理”。结果下面再展示数据来源与时间。冷却中的新公告要说明已保留，用户暂停则说明检查已经停止。

同一价格规则已提醒和出现新公告是不同事件，不能合并成含糊的“异动”。故障记录和条件提醒分别标识。原始数据、版本及摘要保留在可展开的详情，不给它们添加不存在的安全保证。

### 演示体验

演示页提供默认黄金任务和顺序清楚的情景：未达条件、价格触发、重复触发、新公告、来源异常和恢复。具体故障按钮可以保留在详细测试区域。它们是评审验证功能的入口，主使用流程不需要展示它们。

演示页面清楚显示模拟数据以及演示时钟。新访客可以验证，已有真实任务保持原数据模式。退出演示不留下普通用户无法识别的活动测试任务。

### 帮助与技术说明

用户指南按操作组织，技术说明继续保留架构、调用记录和测试口径。网页里出现的每项能力说明必须有实际功能对应。没有跨设备同步时明确说明访客任务如何访问，不使用“本地保存”暗示数据只在设备上。

## Gemini 建议中的必要校正

| 建议 | 本项目处理 |
| --- | --- |
| “达到3%”改为“跌超3%” | 不采用。前者包含等于，后者是严格超过；文案必须保留原比较含义 |
| 未触发写成“股价平稳，未见异常异动” | 不采用。没有触及用户规则不能证明市场平稳 |
| 摘要改成“已加密防篡改存证” | 不采用。现有规则摘要不提供此保证 |
| 展示过去3个月预计触发1至2次 | 未做统计，不展示估计值；未来有完整数据和方法后再加入 |
| 全部去掉结构化确认 | 不采用。题目要求规则可检查、可修改，TradingView也有提醒设置；调整可见层级即可 |
| 归档后直接提供撤销 | 先检查后端。当前归档不能恢复，因此保留清楚确认；实现真正的撤销后才更换交互 |
| 宣称全天候值守与同步备份 | 不采用。当前托管与访客访问机制不能支持这种承诺 |
| Apple从不使用模态提示 | Apple官方建议减少不必要提示，同时明确允许重要且不可撤销操作的确认；按操作后果选择 |

## 实施顺序和完成定义

先完成主工作台与确认页的信息重排，再处理检查详情和演示入口，随后更新用户帮助。最后统一视觉细节并重录视频。每完成一屏，应将同一视口、同一状态的参考图与实际页面并排检查；不能仅凭生成的CSS或DOM断言视觉相似。

以下功能必须在改版后保留并复测：自然语言生成规则、人工确认与修改、严格阈值、或/且组合、价格与公告去重、冷却中新公告保留、来源异常与恢复、暂停/到期/归档、规则版本及重启恢复。视频、README和提交清单跟随最终发布版本更新。

页面能打开、测试全部通过和视觉体验达到参考标准是三项不同的验收。本轮已完成界面实现与上述功能验收；同状态逐屏视觉对照和新版视频仍有待补齐，完整提交包尚未据此宣告完成。
