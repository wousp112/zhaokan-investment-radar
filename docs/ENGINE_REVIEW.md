# 规则与调度补充审查

2026-09-21 对可运行版本追加了以下修复，相关用例位于 `tests/test_regressions.py`。

| 发现 | 修复 | 验证 |
| --- | --- | --- |
| 同一句话包含涨跌幅与绝对价格时，本地解析会遗漏后一个价格条件 | 两类价格条件分别提取，保留组合关系 | 跌3%或股价低于1500元，应生成两条条件 |
| 量比“超过”被解析为“大于等于” | 分别保留严格与包含比较符号 | 超过、达到、低于、不高于四组边界 |
| 本地解析不支持的涨跌幅比较可能被反向理解 | 请求明确表达，避免错误生成规则 | 跌幅低于、涨幅不超过、下跌小于三个反例 |
| 全局任务锁使一个慢来源阻塞其他任务 | 每个任务独立加锁，调度最多四个并发检查 | 挂起一个真实来源请求，同时完成另一个演示任务的检查 |
| 模型要求澄清或输出校验失败后，诊断依据不够完整 | 保存最终输出、结束原因、用量、提示词版本及校验状态 | 评测文件可区分连接失败、结构校验和主动澄清；不保存内部推理文本 |
| 后续评测覆盖默认文件，可能使历史说明与数字不一致 | 报告生成器从单独保存的基线文件读取首轮结果 | 初始结果与最终复测分别保留 |
| 小数报价在二进制浮点相减后，恰好涨跌3%可能被判断为严格超过3% | 用十进制原始报价计算比例后再序列化 | 昨收20元，现价19.40元和20.60元的两个边界用例先重现失败，修复后同时核对严格与包含比较 |

当前编译器提示词版本为 `1.1`。源文件变化后应重启应用进程，使公开服务加载相同代码，再运行浏览器验收。单元与 API 测试的实际计数以 `artifacts/pytest-results.xml` 为准，不能将固定用例通过率解释为开放域准确率。
